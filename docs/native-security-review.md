# Native runtime security review

This is a source-level applicability review, not an independent security assessment or a clean vulnerability scan. Preserve the unmodified scanner reports, package versions and immutable image identities. The 2026-10-04 managed-runtime scans have no CRITICAL or fixable-HIGH blockers, but still contain 47 coordinator and 56 C++ package/advisory pairs at HIGH without a vendor fix. Several pairs refer to the same advisory across related packages. Deployment operators must re-scan before publishing a candidate.

## Mitigated native network paths

The C++ worker explicitly selects `GRPC_DNS_RESOLVER=native` before creating its gRPC channel. For its ordinary host:port channel this selects libc `getaddrinfo()` rather than the bundled c-ares resolver, as documented in the [gRPC 1.51.1 environment-variable reference](https://github.com/grpc/grpc/blob/v1.51.1/doc/environment_variables.md). The c-ares package remains present in the image and is still reported for CVE-2026-33630, CVE-2026-69184 and CVE-2026-69186. This change reduces exposure through the selected resolver; it does not constitute a vendor patch or validate arbitrary xDS/resolver configurations. The actual C++ hostname/TLS replica test must pass with this configuration.

Both native Docker transfer paths explicitly disable ambient proxies and restrict libcurl to HTTP through the configured local Unix socket. URLs are constructed by the trusted agent, each request creates a fresh handle, and redirects are not enabled. See the official [protocol restriction](https://curl.se/libcurl/c/CURLOPT_PROTOCOLS_STR.html) and [proxy control](https://curl.se/libcurl/c/CURLOPT_PROXY.html) documentation. SSH/SFTP, public TLS, authenticated proxy and shared connection-pool behavior are not part of these Docker request paths. This constrains the affected behavior reported for CVE-2026-12064, CVE-2026-8286, CVE-2026-8458 and CVE-2026-8927; the package findings remain unresolved and these observations are not general claims about other programs using libcurl.

The worker is a gRPC client with bounded call deadlines and response limits. The reported gRPC advisories CVE-2023-33953, CVE-2023-44487 and CVE-2023-4785 include server/HTTP2 resource-exhaustion behavior. Strata's coordinator uses its separately locked, newer Python gRPC runtime. Client-only placement limits server-listener exposure, but it does not establish that an older native client is safe against every malicious peer. Require a private, verified TLS coordinator endpoint in production and review any residual client behavior before external deployment. No blanket exception or suppression is applied.

## Operating-system findings

The util-linux advisories CVE-2026-76642, CVE-2026-78408, CVE-2026-78409 and CVE-2026-78410 concern privileged mount/namespace/helper behavior. Strata does not invoke these programs to interpret workload requests. Workload containers run without capabilities, with a read-only root filesystem and no-new-privileges. Output/input mounts are created by the trusted Docker agent, not by a privileged workload. The Docker socket still grants its trusted agent host-level authority; never mount it into a workload or allow an untrusted administrator to configure execution images, infrastructure or endpoints. These boundaries reduce workload reachability without patching the installed packages.

The remaining reported ACL, ncurses, Perl Archive::Tar and systemd findings need package- and deployment-specific review. Strata does not use Perl Archive::Tar to unpack workload output, run systemd-homed inside these images, or grant workloads host ACL authority. Python/C++ artifact collectors inspect bounded regular files without extracting worker-controlled archives onto the host. The custom libarchive build disables unsupported archive backends and carries an explicit static-source inventory. Unused component placement is supporting evidence, not proof of absence of every execution path or an authorization to remove the findings from raw reports.

## Release consequences

The automated candidate gate rejects all CRITICAL and fixable HIGH findings. Unfixed HIGH findings remain visible and require a human applicability/security decision; passing that gate alone does not approve production use. Keep the deployment private until its identity, TLS, daemon authority, backup/restore, host/kernel and unresolved-advisory reviews are satisfied. The local functional/fault tests validate specified boundaries and recovery paths. Independent testing, physical failure-domain measurements, cloud billing controls and unknown vulnerabilities are outside that evidence.
