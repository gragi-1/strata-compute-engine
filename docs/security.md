# Security boundaries

This document describes the trusted Docker execution boundary shared with the v2 release. The unreleased product expansion adds [individual/federated identity, project isolation and quotas](identity-and-projects.md), [whole-device GPU reservations](gpu-execution.md), and [current dependency/image verification](security-verification.md). Shared role-key descriptions below apply to legacy local mode; project-owned data requires individual identity. These additions do not make Docker-socket agents safe for arbitrary untrusted tenants.

Strata executes only images on the API and worker allowlists. Bundled workloads run as UID/GID 65534 with CPU quotas, hard memory/swap limits, PID limits, dropped capabilities, no-new-privileges, no network, a read-only image filesystem and a bounded `/tmp` tmpfs. Docker provides the actual isolation and accounting; [Docker resource constraints](https://docs.docker.com/engine/containers/resource_constraints/) describe those controls.

Workload containers enable Docker's init process to forward termination signals and reap children. This avoids relying on a workload running as PID 1 to handle the default stop signal; see [Docker's init and signal behavior](https://docs.docker.com/reference/cli/docker/container/run/).

The current Python and C++ agents enforce kernel byte/inode limits on each writable output volume and retain its tmpfs mount through container exit using a bounded, credential-free helper. Accepted artifact transfers have separate size limits. This requires the reviewed keeper image and Linux tmpfs `noswap` support; older v2 agents do not provide this output guarantee. See [storage budgets, output limits and retention](storage-retention.md) for configuration, memory accounting, lease expiry and the current 16 MiB C++ transfer ceiling. Only trusted allowlisted workload images belong on this cluster. Mutable local tags are convenient for demos; use immutable digests and restrict image publication for remote deployment.

Agents have the Docker socket, which grants administrator-level daemon access. Workload containers do not receive that socket or host-directory mounts. Agents are trusted infrastructure, not an untrusted tenant boundary. Their shared bearer token is configured by environment; the committed default is explicitly a local development value.

Compose publishes all ports to 127.0.0.1. The default remains local development mode: empty `STRATA_API_KEYS` permits local REST access. In the v2 expansion, configured bearer keys enforce `viewer`, `operator` and `admin` roles on business routes. Keys are shared role credentials, compared with constant-time equality, and must contain at least 24 characters. Public health/readiness, static UI, OpenAPI and telemetry routes do not return worker credentials. The internal scheduling endpoint requires the separate worker token. Keep telemetry/internal routes private.

The web workspace stores its API key in browser session storage. It uses a strict content security policy with local scripts/styles and renders user data as text. API CSV exports and CLI reports neutralize leading spreadsheet formula characters in string cells. Treat downloadable files as application data; an allowlisted workload can still generate arbitrary artifact content.

Both worker implementations support verified gRPC TLS through a trusted CA certificate, with hostname verification enabled. `STRATA_PRODUCTION=true` requires configured role keys or enabled individual identity, a strong worker token and the RPC certificate/key configuration. Individual identity additionally requires a bootstrapped enabled platform administrator before readiness succeeds. REST HTTPS must be provided by the supplied Caddy template or an equivalent protected proxy. The template preserves the application's stricter workspace CSP; OpenAPI documentation uses FastAPI's standard documentation assets. See [deployment](deployment.md) for certificates, network restrictions and immutable image allowlists.

Inputs are downloaded in lease-authorized ranges, verified by SHA-256 and mounted read-only. Dataset versions become immutable after sealing. Input caches, Docker images, backups and unrelated host applications remain outside the workload output quota and need their own capacity monitoring. Legacy shared API keys do not establish per-user ownership or project quotas. Enable [individual identity and projects](identity-and-projects.md) for private project resources, memberships, revocable credentials, audit and atomic project budgets. These application controls do not replace the trusted workload/host boundary or make Docker a hardened isolation system for arbitrary hostile tenants.

Protect database dumps and backups: they contain data, logs and internal attempt credentials. Keep private TLS keys and role/worker keys out of Git. The templates do not expose Docker daemons over a public network. The independent-daemon validation uses disposable privileged Docker-in-Docker test fixtures on a private Docker bridge; those fixtures are not a production deployment design. Strata remains a trusted-cluster system and does not claim production multitenant isolation.
