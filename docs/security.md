# Security boundaries

Strata executes only images on the API and worker allowlists. Bundled workloads run as UID/GID 65534 with CPU quotas, hard memory/swap limits, PID limits, dropped capabilities, no-new-privileges, no network, a read-only image filesystem and a bounded `/tmp` tmpfs. Docker provides the actual isolation and accounting; [Docker resource constraints](https://docs.docker.com/engine/containers/resource_constraints/) describe those controls.

Workload containers enable Docker's init process to forward termination signals and reap children. This avoids relying on a workload running as PID 1 to handle the default stop signal; see [Docker's init and signal behavior](https://docs.docker.com/reference/cli/docker/container/run/).

The output volume is writable and retained through container exit so artifacts can be uploaded. API/archive limits bound accepted output bytes, but do not enforce a disk quota on that volume. Only trusted allowlisted workload images belong on this local cluster. Mutable local tags are convenient for demos; use immutable digests and restrict image publication for remote deployment.

Agents have the Docker socket, which grants administrator-level daemon access. Workload containers do not receive that socket or host-directory mounts. Agents are trusted infrastructure, not an untrusted tenant boundary. Their shared bearer token is configured by environment; the committed default is explicitly a local development value.

Compose publishes all ports to 127.0.0.1. The default remains local development mode: empty `STRATA_API_KEYS` permits local REST access. In the v2 expansion, configured bearer keys enforce `viewer`, `operator` and `admin` roles on business routes. Keys are shared role credentials, compared with constant-time equality, and must contain at least 24 characters. Public health/readiness, static UI, OpenAPI and telemetry routes do not return worker credentials. The internal scheduling endpoint requires the separate worker token. Keep telemetry/internal routes private.

The web workspace stores its API key in browser session storage. It uses a strict content security policy with local scripts/styles and renders user data as text. API CSV exports and CLI reports neutralize leading spreadsheet formula characters in string cells. Treat downloadable files as application data; an allowlisted workload can still generate arbitrary artifact content.

Both worker implementations support verified gRPC TLS through a trusted CA certificate, with hostname verification enabled. `STRATA_PRODUCTION=true` fails startup when role keys, a strong worker token or the RPC certificate/key configuration are missing. It does not create REST HTTPS: the supplied Caddy template or an equivalent protected proxy must provide it. The template preserves the application's stricter workspace CSP; OpenAPI documentation uses FastAPI's standard documentation assets. See [deployment](deployment.md) for certificates, network restrictions and immutable image allowlists.

Inputs are downloaded in lease-authorized ranges, verified by SHA-256 and mounted read-only. Dataset versions become immutable after sealing. File/archive limits bound accepted bytes and preview work, while the execution host and blob filesystem still need storage monitoring. Output volumes have no enforced filesystem quota. API keys do not provide per-user ownership, tenant isolation or per-user quotas.

Protect database dumps and backups: they contain data, logs and internal attempt credentials. Keep private TLS keys and role/worker keys out of Git. The templates do not expose Docker daemons over a public network. The independent-daemon validation uses disposable privileged Docker-in-Docker test fixtures on a private Docker bridge; those fixtures are not a production deployment design. Strata remains a trusted-cluster system and does not claim production multitenant isolation.
