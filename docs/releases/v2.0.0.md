# Strata v2.0.0: Compute Workspace

Strata v2 expands the durable execution engine into a workspace for organizing data, running containerized CPU programs and collecting reproducible results. Use your own allowlisted images for simulations, data-processing stages and other finite batch computations.

## New capabilities

- A web workspace for jobs, attempts, logs, artifacts, datasets, campaigns and worker capacity.
- Immutable dataset versions with content hashes, bounded CSV/TSV/JSON/NumPy/Parquet previews and verified read-only input staging on both worker implementations.
- Atomic parameter campaigns with matrices, repetitions, idempotency, progress, cancellation/retry and CSV/JSON result exports.
- Validated dependency workflows with successful predecessor artifact transfer and failure propagation.
- A synchronous Python SDK for scripts/notebooks, expanded CLI commands and scientific PNG/PDF reports with provenance.
- Viewer/operator/admin API roles, verified gRPC TLS, fail-closed production configuration, worker draining and trusted-network deployment templates.
- Consistent PostgreSQL snapshot backups, verified blob manifests, restore into empty targets and non-destructive storage auditing.
- Seeded Monte Carlo uncertainty metrics and streaming numerical dataset profiling examples.

## Verification

Local validation recorded **92 passing Python tests**, **93.38% control-plane/scheduler coverage**, a complete C++ build and **2/2 CTest successes**. Real Docker checks covered both agents, cancellation, timeouts, RPC loss, read-only dataset inputs, a successful dependency workflow and **48/48 successful campaign jobs**. Both implementations also ran dataset profiling through verified TLS on two independent Docker daemons on one physical computer. A browser-uploaded CSV was processed through the public SDK and its downloaded result was checked by hash and length.

See [validation evidence](https://github.com/gragi-1/strata-compute-engine/blob/v2.0.0/docs/validation-v2.md) for the environment, recorded results and test scope. GitHub CI must pass for the tagged commit before this release is published.

## Upgrade from v1

Back up the database and blob store before upgrading. Keep both in durable storage. Apply the additive Alembic migration before starting v2 services; the standard Compose migration service handles this dependency. Rebuild the control plane and both worker implementations. New dataset inputs require workers advertising `dataset-inputs`, so older agents cannot receive those jobs.

The local development stack keeps loopback ports, an open REST API and a development worker token. Trusted-network deployments need role keys, strong worker credentials, verified RPC TLS, REST HTTPS, protected database/telemetry services and consistent allowlisted image digests. See [deployment](https://github.com/gragi-1/strata-compute-engine/blob/v2.0.0/docs/deployment.md) and [the workspace guide](https://github.com/gragi-1/strata-compute-engine/blob/v2.0.0/docs/platform.md).

## Scope

This release targets finite CPU batch programs in trusted teams. GPU allocation, elastic provisioning, SSO/tenant isolation, object-store storage, automatic retention and database failover are not implemented. Independent-daemon validation does not establish physical multi-machine speedup; the development environment had one computer. Resource limits and output/input bounds remain configurable, and sufficient host disk space is required for images, data staging, outputs and backups.
