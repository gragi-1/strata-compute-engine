# Data-driven workflows

`strata workflow examples/dynamic-workflow.yaml --idempotency-key study-v1` runs an adaptive study whose experiment count is determined by the first job's output. The same specification can be submitted from **Campaigns → New workflow**, `Client.workflow()` or `POST /workflows`.

An `expansions` entry names a container source node, one JSON artifact and a job template. After the source succeeds, Strata reads the artifact from that successful attempt and creates one child per parameter object. `${parameter}` substitutes within individual command arguments; there is no shell or expression evaluation. Generated jobs retain their parameters, expansion name and item index. The expansion records its manifest SHA-256 and generated count.

Each expansion also creates a coordinator join node under its name. Downstream nodes can depend on it. The join succeeds after all generated children succeed, fails on a failed child and consumes no worker or container. It remains visible in campaign progress so the workflow's state is explicit. An empty parameter array completes the join without creating containers. A downstream `all_terminal` or `any_failed` condition can perform cleanup or report failure.

An artifact input referencing the join collects the named artifact from each successful child. For `alias: results`, files appear at `/inputs/results-0/result.json`, `/inputs/results-1/result.json`, and so on. These effective aliases and original artifact IDs are frozen in attempt provenance; replay pins the resolved child artifacts. Join artifact aliases have a 24-character limit to leave room for item indexes. Resolved paths may not overlap.

Expansion is one transaction. Concurrent scheduler processes create one set of children. A malformed item or invalid rendered job rolls back every child before marking the join failed; a queue quota failure retains the expansion and retries after 30 seconds. Current owner permissions and project budgets are checked at expansion time. Campaign retry requeues failed children and their join together, and retains already generated jobs. A failed source can be retried without losing its earlier attempt history.

Limits are 1 MiB per parameter artifact, 1,000 children per expansion, 16 scalar parameters and 16 KiB per parameter object, 100 expansion definitions and the configured total campaign job limit. Templates accept sealed datasets, with the source dependency added by Strata. Arrays must contain objects; missing parameters, nested values, non-finite numbers and reserved parameter names are rejected. Source nodes and expansions participate in cycle detection. Source artifacts are immutable and the source must have succeeded.

Inspect status, count, hash and errors in campaign details, `strata workflow-expansions CAMPAIGN_ID`, `Client.workflow_expansions()` or `/campaigns/{id}/expansions`. Migration `0008` adds expansion records and the internal execution kind. Existing jobs default to container execution. Tests cover atomic rollback, quota recovery, cancellation/retry, empty expansion, private resources, concurrent PostgreSQL expansion and actual Docker child-to-join artifact transfer with both workers.
