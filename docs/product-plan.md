## Current environment constraints

The available environment has one physical Windows computer. The initial sandbox-reported free space on C: was about 262 MiB; a host check subsequently showed about 49 GiB. The user initially authorized F:, but Windows later reported device I/O failures and failed test writes. Its test services were stopped. At the user's request, the active environment, caches, isolated PostgreSQL cluster, S3 test objects and browser fixtures now use ignored directories under the repository on C:. Existing source files remain on C:. An available RTX 3050 Laptop GPU has now passed actual CUDA execution through both agents. Physical multi-host and multi-GPU measurements still need additional hardware. No cloud provider, infrastructure budget or production identity provider has been supplied. Federated sign-in has been validated with an isolated synthetic Keycloak realm.

These constraints must remain visible in the evidence. Request the missing prerequisites when needed and continue independent implementation. Never replace a failed live check with a passing mock and label the capability operationally verified.

## Work order

1. Establish individual identity, project isolation, admission/execution/storage budgets and audit before exposing new data or execution modes.
2. Introduce storage abstraction and resumable transfer, then large-data queries, retention and worker caches.
3. Complete experiments, workflows, fair scheduling and all web/CLI/SDK paths with meaningful tests.
4. Add GPU, multi-node and interactive runtime paths together with their actual failure semantics.
5. Add supervised operations, high-availability and provisioning adapters, distribution automation and sustained validation.

Keep this ledger updated with concrete implementation and test references. A final release requires all agreed groups to be completed or an explicit user-approved change in scope; lack of time or context alone is not acceptance.

## Local evidence, 2026-10-03–04

The final integrated suite passed **273 tests** with real PostgreSQL 17, Versity S3 and every available Docker/GPU/failover check enabled, with no failures/errors/skips and **90.27%** coordinator/scheduler coverage. It includes bounded output/helper accounting, cooperating computation, notebooks/services, batch renewal, ambiguous-start reconciliation and maintenance fencing. An isolated one-hour submission run completed **1101/1101 real workloads** (551 Python-agent, 550 C++-agent), with no job retries, one attempt, verified downloaded outputs and exactly zero final reservations. Four native tests, three final-image quota checks and 21 authored browser regressions passed. Fresh installed wheel checks passed through migration 0017 with ten entrypoints, HTTP/readiness/web and both runtime client command groups. Independent wheel/sdist builds were byte-identical at a fixed source timestamp. Earlier failed and suspended runs remain visible in [v3 validation](validation-v3.md), together with image identities and scope.

The later replica tests passed for both workers using verified RPC TLS, independent coordinator caches and shared actual S3 bytes. One coordinator was killed while a container ran; the same job kept one attempt, released its reservation and delivered output through both replicas after restart. The final integrated run recorded 0.21 seconds to the first survivor API response for the Python path and 3.42 seconds for C++. PostgreSQL primary recovery took 24.48 seconds, and write authority was withdrawn 8.68 seconds after DCS quorum loss. These are individual observations on one host, not an availability SLO or every client's recovery time. Actual lost-after-commit HTTP replies, silent libpq peers and terminated transactions are covered by the store/retry tests. Production replicas reject unverified PostgreSQL and unshared filesystem storage.

The minimal PostgreSQL 17.11 image passed all 225 upstream regression tests during its build. The reviewed PostgreSQL, gateway and etcd images pass the CRITICAL/fixable-HIGH gate; the PostgreSQL image still has 44 unresolved HIGH package/advisory pairs requiring applicability review. The gateway and etcd reports have no HIGH/CRITICAL findings. Patroni's separately hashed dependency graph has no known advisories. Previously audited coordinator/workload images retain their explicit unresolved HIGH reviews. No final security clearance is claimed.

Browser checks on isolated localhost fixtures covered sign-in, projects, administration/audit, five-format datasets, resumable uploads, queries/charts, experiments, schedules, workflows, webhook history, actual backup/restore history, maintenance admission controls, elastic pool bounds/drain and GPU discovery. A real 30-second CPU job displayed live logs and its final output automatically. A 390-pixel viewport showed bounded, keyboard-focusable scrollable tables without page overflow. The seven authored regressions now pass in Chromium, Firefox and WebKit (21 cases), including native accounts/projects, real committed reply-loss submission recovery, group/session lifecycle and mobile keyboard focus. Configured axe WCAG checks pass across all eleven navigation pages and the tested forms/mobile view in all three engines; manual assistive-technology and broader dynamic-state review remain pending.
